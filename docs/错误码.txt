============================================================
         多平台视频下载工具 错误与排查手册
         对应版本：v2.8.0 WebUI（Windows EXE／源码运行版）
============================================================

本手册按报错来源说明退出码、HTTP 状态、FANBOX 错误标识和任务状态。
先看具体错误文本及其前后的日志，不要只凭最后一个数字判断故障原因。

一、先分清看到的是什么
------------------------------------------------------------
1. 进程退出码：例如“下载结束，退出码: 1”，表示某个下载器或命令的结果。
2. HTTP 状态码：例如 HTTP 403、404、429，表示远端服务器的响应。
3. 应用错误标识：例如 lease_expired、invalid_payload，表示程序中的具体检查结果。
4. 任务状态：例如 queued、partial、stopped，不是进程退出码。

同一个数字在 yt-dlp、FFmpeg、fantiadl、Withny 或主程序 CLI 中可能含义不同，不能共用一张固定映射表。
进程返回 0 也不一定下载了新文件：命中归档、跳过已有文件或只执行预览时都可能正常结束，请同时检查任务统计与输出文件。

二、yt-dlp 退出码与常见文本
------------------------------------------------------------
适用范围：日志明确来自 yt-dlp 或其外部下载器的场景。

退出码 0：正常结束，仍需核对成功、跳过数量及实际输出。
退出码 1：通用失败。提取、登录、网络、下载或后处理失败均可能返回 1。
退出码 2：命令行参数解析或调用错误，检查自定义参数、拼写及参数值。
退出码 101：yt-dlp 的 DownloadCancelled 提前结束，例如达到 --max-downloads 或命中相应停止条件；不能直接等同 WebUI 的“停止”。
其他退出码：结合工具名称与完整日志判断，不把 3、4、5、8、22 固定解释为权限、网络、删除或中断。

常见提示与处理：
- Requested format is not available / 无可用格式：先用自动画质与兼容输出组合复查，放宽格式筛选；这是运行失败，不能仅据此认定为退出码 2。
- Sign in / login required / private / members-only：先在浏览器确认同一账号有观看权限，再更新对应登录态。
- This video is protected by a password：TwitCasting 内容需要密码；通过 WebUI 对应任务输入正确密码，不能把密码直接当 Cookie 使用。
- has already been recorded / 已记录在下载归档：表示命中记录，不证明磁盘文件仍存在；按任务提示选择重新下载或跳过。
- Unsupported URL / 不支持的链接：核对平台和链接类型，普通视频、主页、直播、列表可能使用不同入口。
- DownloadError / ExtractorError：查看其具体消息；更新 yt-dlp 只能修复部分提取问题，不能授予账号权限。

三、HTTP 与网络错误
------------------------------------------------------------
HTTP 400：请求无效、参数或签名不再有效，也可能与接口变化有关。重新从原始内容链接发起任务，勿长期复用日志中的临时媒体地址。
HTTP 401：请求未通过身份验证。检查登录方式、Cookie 或令牌是否有效。
HTTP 403：服务器拒绝访问。可能是账号权限、签名过期、验证要求、地区或请求限制，不能仅凭 403 断定 Cookie 过期。
HTTP 404：资源不存在，或对当前账号不可见。核对原始链接与浏览器中的访问结果。
HTTP 429：请求过于频繁。暂停并按平台或 Retry-After 提示等待，降低并发，不要连续重复提交。
HTTP 5xx：平台或上游服务异常。保留日志，稍后重试。

Connection refused / 连接被拒绝：检查程序中配置的代理地址、端口及代理服务是否运行。
代理开关并非全部请求的总开关：主要下载路径关闭后默认直连，更新及部分探测仍可能沿用系统／环境代理；自定义 --proxy 和系统 TUN／VPN 也会影响出口。
Timed out / 超时、DNS 解析失败：分别检查网络、域名解析和代理；浏览器可访问不代表下载器使用了同一条网络路径。
SSL / certificate / TLS 错误：检查系统时间、代理及完整依赖；不要通过关闭证书验证来掩盖问题。

四、FFmpeg、HLS 与本地文件
------------------------------------------------------------
提示：ffmpeg exited with code 4294967294
  这是 Windows 可能显示的 32 位无符号退出值，对应有符号 -2。
  该数字本身不能唯一定位原因。请向前查找 FFmpeg 的具体 stderr，例如输入无法打开、权限不足、HTTP 请求失败、无效媒体或封装错误。

提示：Initialization fragment found after media fragments, unable to download
  表示 HLS 清单在媒体分片后出现初始化段，yt-dlp 原生 HLS 路径可能无法处理。
  本版 TwitCasting 会使用并发预取插件及 FFmpeg 回退路径。先等待程序的恢复或重试结果，不要把中间一次报错直接当作最终失败。
  如果最终仍失败，完整更新 EXE 和依赖包，检查 FFmpeg、平台插件以及日志中最近的 HTTP、登录或文件错误；保留尚未完成的缓存，不要盲目关闭所有并发或删除文件。

常见文件与媒体提示：
- ffmpeg / ffprobe 未找到：确认 dependency/ 位于 EXE 同一目录，完整解压同版本依赖包。
- No such file or directory / 无法打开输入：检查实际输入路径、临时文件是否仍在；不要仅依据退出码猜测缺失文件。
- Permission denied / Access is denied：检查输出目录写权限、文件是否被播放器占用，以及磁盘是否只读。
- No space left on device：检查下载目录和临时目录的可用空间。
- Invalid data found / 解码失败 / 文件头不符：输入可能不是媒体、下载未完整或已损坏；保留原始片段并核对来源与权限。
- 合并、封装或嵌图失败：检查音视频轨道和输出组合；部分组合只保存独立封面，不支持嵌入。

.part、.ytdl 或分片文件表示恢复数据，不是最终视频。未完成时不要随意删除；视频确认完成后，程序会按对应路径清理可删除的恢复数据。
普通视频与不同平台的续传能力不同；Rplay 未完成媒体会按当前实现重新下载，不能承诺所有内容都从断点继续。

五、FANBOX 错误标识
------------------------------------------------------------
FANBOX 的 code 是应用错误标识，不是 yt-dlp 的数字退出码。相同 code 应结合 message、任务阶段和资源明细查看。

【配置、凭据与依赖】
- cookie_file_missing：配置中指定的凭据文件不存在。检查 FANBOX 凭据路径；相对路径以程序目录为基准。
- cookie_file：Cookie 文件无法读取、格式不合要求或超过大小限制。使用 Netscape 格式；文件成功加载不等于平台确认登录有效。
- dependency_missing：运行库缺失，或代理/SOCKS 依赖及配置不可用。EXE 用户重新完整解压同版本安装文件；源码用户按教程安装锁定依赖。
- platform_disabled：FANBOX 已关闭。检查平台专项设置。
- invalid_config / invalid_json / file_too_large：配置、JSON 或输入大小不符合要求。检查对应配置文件，不要先删除账号数据。
- invalid_url / scope_required / unsupported_scope：来源链接或集合范围不受支持。检查创作者、单帖或账号集合入口。

【权限与服务】
- access_denied：当前请求未获授权。核对账号权限、登录态和浏览器验证状态；匿名访问仅适用于公开内容。
- challenge_required：接口返回浏览器验证或非预期验证页面。先在平台处理验证，程序不会自动绕过。
- rate_limited：平台限频或本地账号冷却中。按 retry_after 等待；不要在冷却期间不断重试。
- not_found：投稿、作者或附件不存在，或当前账号不可访问。
- network_error / server_error / http_error：网络请求、服务端或未预期 HTTP 状态错误，结合 message 及前文日志排查。
- unexpected_redirect：接口或资源返回了未预期重定向。检查原始来源与登录状态，不要手动信任跳转后的任意地址。
- schema_changed：接口结构、字段类型或内容身份不符合预期。保留脱敏错误信息，检查后续兼容更新。

【任务与恢复】
- job_busy：归档仍在排队、运行、收尾，或与校验/缓存操作互斥。先核对任务及日志，不要重复启动同一任务。
- stale_version：任务已被其他操作更新。刷新任务详情后再操作，不要重用旧页面中的版本数据。
- queue_rejected：启动或入队请求被拒。按 message 处理当前任务占用或启动条件，再重试。
- request_conflict：同一请求标识对应了不同参数。刷新界面并重新提交，避免重复发送旧请求。
- credentials_changed：恢复时登录快照与原任务不一致。确认需要的账号后创建新抓取任务，不要手改数据库绕过检查。
- invalid_checkpoint：来源、配置、登录状态或检查点结构不匹配。使用一致的任务条件恢复，无法匹配时创建新任务。
- lease_expired：工作或下载租约已过期，不能证明任务仍在运行。当前源码会在等待期间每 20 秒续租，并在异常结束时原子保存终态；若仍遇到该错误，请核对日志与任务状态后继续。原发布附件的相关问题见第八节。
- cancelled：该操作收到取消信号。FANBOX 归档可能保存为 paused，以便继续；校验也可能单独被取消。
- job_not_found / post_not_found / output_missing：任务、投稿详情或本地归档入口不存在。刷新列表并核对实际文件是否已移动。
- nothing_to_retry / nothing_to_verify：没有可单独重试或校验的资源，不能据此判断所有资源均完整。
- verification_busy：已有资源校验在执行。先等待或停止该次校验。

【文件、额度与策略】
- quota_exceeded：当前可用下载额度不足，可能涉及资源大小、每日额度及计量时区。
- quota_busy：额度被其他正在进行的下载预留。等待相关任务结束或检查并发，不代表当天流量已全部用尽。
- fallback_required：原图不可用，等待图片质量策略选择。调整允许的回退策略后继续；降级结果不等于原图成功。
- conflict_required / path_conflict：目标文件冲突或无法分配唯一名称。检查同名处理策略和命名模板，保留已有文件。
- invalid_template / unsafe_path：命名模板或路径不符合规则。检查模板字段及输出位置，不要关闭路径检查。
- invalid_payload：资源返回了网页、错误文档，或图片签名/解码不符合预期。核对权限与实际响应内容；当前源码已修复 JPEG 缩略图沿用 PNG/GIF 扩展名的问题，旧失败资源续跑时可修复路径。
- incomplete_file / invalid_range / invalid_response：资源不完整，或响应长度、续传范围、头部不符合检查要求。保留恢复数据，核对后重试。
- range_restart：服务器拒绝续传或文件版本改变，下载器可能重新下载；关注任务最终结果。
- resource_changed：资源大小等信息已改变。重新抓取投稿，避免把新旧资源当作同一个文件。
- response_too_large：接口正文或资源响应头超过保护上限。保留错误，不要直接关闭大小限制。
- unsafe_api_url / unsafe_resource_url：接口或资源地址不符合允许的来源规则。核对原始帖子，不要强行下载拒绝的地址。
- database_version：数据库版本较新或结构无法识别。备份数据，使用兼容程序，不要直接删除数据库。
- no_supporting_creators / card_scope_required / card_background_failed：没有可用赞助粉丝卡、需明确粉丝卡集合范围或背景下载失败。核对当前账号和任务选项；部分内容归档与粉丝卡失败应分别查看。
- executor_error / archive_error：执行器或归档写入/响应处理失败的汇总错误，需结合前文日志与磁盘状态，不能据此固定归因为网络。

六、Rplay、Fantia 与外部录制组件
------------------------------------------------------------
【Rplay】
- login required / private / firefox_rplay_login_required：登录内容需在 Firefox 中具有有效登录态，并在程序中选择正确配置；普通 cookies.txt 不能替代此授权。
- rplay_login_expired / rplay_refresh_failed：登录已过期或续期失败。重新在 Firefox 登录，结束失败任务后重新发起。
- rplay_auth_lock_timeout / firefox_session_snapshot_timeout：等待受保护会话锁或读取快照超时。避免同时重试多次，检查 Firefox 配置是否可访问后再试。
- rplay_auth_requires_windows_dpapi / rplay_credential_protection_failed：会话保护不可用或失败。检查 Windows 运行环境及用户上下文，不要关闭凭据保护。
- is not live：当前未直播。确认直播间链接后选择等待开播，或稍后再试。
- Twitch 转播源不可用/未直播：核对源 Twitch 频道状态及观看权限；Rplay 凭据不会转交 Twitch。
- DRM、未知加密、授权协议暂不支持、无有效播放地址：当前实现无法处理或没有可用授权源。不要通过修改参数绕过权限检查。
- HLS 暂不支持分离音画：选择合并或受支持的音频输出组合。

【Fantia】
Fantia 使用独立的 fantiadl。非零退出码应结合其原始错误消息判断；本项目不提供经核实的 2/3/4 固定映射，不套用 yt-dlp 退出码。
检查 dependency/fantiadl.exe、fantia.jp 导出的 Netscape Cookie、账号订阅与帖子权限。仅支持 Cookie 文件模式。

【BililiveRecorder 与 Withny】
- “录播姬未安装、校验失败或版本不兼容”：完整更新 dependency/BililiveRecorder，保留组件与 manifest。程序可能降级到 yt-dlp 路径，需核对最终日志、录制模式和报告。
- Withny 受管组件：dependency/Withny/withny-dl.exe 与 manifest 应成套保留；受管组件不可用时可能回退旧的 withny-dl-windows-amd64.exe，不能仅凭文件存在认定原生聊天已启用。
- “缺少依赖”：完整更新本版依赖包，不要把其中的 EXE、DLL 或 manifest 单独搬走。
- withny_channels_required / invalid_withny_channel / invalid_withny_channel_params / invalid_withny_quality：YAML 中的频道或参数结构不符合要求，按 Withny 配置指南检查。
- HAR 存档提示加密、DRM、清单正文缺失或签名 Cookie 不支持：检查是否导出了包含内容的完整 HAR；只处理已授权且当前支持的普通未加密 HLS，不通过删改 HAR 绕过限制。

七、任务状态、录制报告与工具提示
------------------------------------------------------------
【任务队列状态】
queued：等待调度；running：任务执行中；waiting：等待条件满足，具体原因看任务消息。
completed：任务按当前范围完成；partial：仅部分内容成功；failed：失败；cancelled：已取消；stopped：已停止；timed_out：等待或执行条件超时。
这些状态不是数字退出码；同一任务还可能有 FANBOX 归档状态、资源状态及直播完整性结论，需分别核对。

【FANBOX 归档与资源】
preview_ready：预览已就绪，尚未完成下载；paused：归档暂停，查看原因后继续。
partial：可能包含受限、失败、降级等情况；degraded：资源已降级，不能当作原图成功。
reused / skipped：复用或跳过资源，不表示本次重新下载成功；verified 结果还应以具体资源校验报告为准。
queued/running 文字本身不足以证明线程仍在正常工作，应结合具体资源、任务日志和归档清单判断；第八节说明原发布附件与当前源码的区别。

【直播完整性报告】
complete：报告所检查的录制范围通过当前检查，不承诺已取得平台全部历史分片。
from_earliest_available：从可取得的最早内容开始，不等于一定覆盖开播时刻。
gaps：有可用媒体，但存在缺口或警告；failed：没有满足要求的可用结果。
cancelled_before_recording：媒体开始前已取消。评论覆盖和同步精度另看 comments-report.json。

【音频、封面与进度】
- 进度暂为 0%、百分比未知或处于探测/封装：先看日志和任务阶段，不直接判断为卡死。
- 「同时输出音频」先完成视频，再从视频提取配套音频；同一进度条切换到音频阶段后从 0% 重新计算。
- 「音频提取失败，视频已保留」表示配套音频未完成，该链接按失败记录；保留的视频不代表音视频均已成功。检查 FFmpeg、输出目录与具体日志后重试。
- 音频工具提示目录不存在、无支持文件或任务占用：检查目录、输入类型和活动任务后再启动。
- 参数越界、APE 不支持输出、无音轨、解码验证失败：按具体消息调整输出和输入；FFmpeg/ffprobe 必须可用。
- 转换超时：查看日志、文件大小及处理阶段。已有输出可能按工具规则跳过；失败时保留源文件，不承诺固定压缩比例。
- 图片格式或嵌图问题：普通封面与 FANBOX 资源走不同路径，按第四、五节及已知问题排查。

【自动更新】
- 缺少有效 SHA-256、大小不一致、校验失败、来源不可信或无效 EXE：程序会拒绝替换。使用项目 GitHub Releases 的可信附件并核验，不绕过检查。
- 更新下载限制为 512 MiB，并检查 HTTPS 允许来源及重定向、已知文件大小和 Windows EXE 格式。
- 源码版不会被 EXE 自动替换。源码升级应同步主脚本、video_downloader/、resource/ 和依赖；绿色版按对应版本说明更新配套依赖，当前源码可用下方「更新依赖」补齐。

【依赖检测与更新（v2.8.0 新增）】
入口为「关于软件 → 依赖状态 → 更新依赖」。启动或打开时只检测缺失，不自动下载；点击「更新依赖」确认后，才下载当前程序配套的完整包并校验、备份和替换外置组件。以下文字码属于依赖维护，不是 yt-dlp 数字退出码；同名状态需结合报错来源判断。
- unchecked / present / verified / missing / changed：分别表示待检查、已存在、验证通过、缺失、与发布基线不同。启动和打开时不做全目录哈希检查，present 不等于内容校验通过；changed 也可能来自自行更新。自行升级的 yt-dlp 默认保留，其兼容性仍需实际任务验证。
- builtin / source_runtime / readonly_group：EXE 内置或源码 Python 运行库只读，不在运行中替换。EXE 随主程序维护；源码版按 README 或《使用教程》的锁定版本命令准备。
- changed_files：需要处理已变化的依赖文件。核对日志和备份，再按界面确认更新；不要改写可信清单来绕过检查。
- active_tasks / busy：存在下载、队列、音频工具、监控或其他维护操作，先等待或取消相应操作。依赖更新期间暂不能启动新任务。
- invalid_selection / closed：请求参数不符合要求，或依赖更新已关闭。刷新页面后重试；程序退出期间不要继续提交操作。
- invalid_catalog / invalid_release / asset_unavailable：内嵌清单不可用、发布信息无效，或找不到可验证的对应版本完整依赖包。保留具体错误，通过界面的「前往 GitHub 手动下载依赖」检查项目官方发布页；不要把当前安装文件直接当作可信基线。
- archive_size_mismatch / archive_hash_mismatch / file_hash_mismatch / missing_archive_files / post_install_verification_failed：包大小、包或文件 SHA-256、文件集合、安装后复核未通过。停止使用该候选，检查网络、磁盘和同版本官方附件，不绕过校验。
- untrusted_source / unsafe_archive / unsafe_path：来源、重定向、归档路径或文件类型不安全，可能涉及路径穿越、链接、重复项或解压限额。使用官方发布附件，保留报错，不关闭保护。
- insufficient_space：可用磁盘空间不足。先停止操作，检查依赖目录所在磁盘及维护缓存空间，保留个人数据与恢复备份后再释放空间。
- concurrent_modification / recovery_required：依赖在维护期间被其他程序修改，或发现未完成的事务、备份不完整或不兼容。保留 download/.dependency-manager/ 及日志，按界面继续更新以先恢复备份；恢复完成前不能启动新任务。未完成维护先在原版本恢复再升级；已升级遇清单不兼容时回原版本恢复或人工处理，不删除备份。
- cancelled：已取消本次操作。取消或失败会尝试恢复已备份文件，等待完成；若同时提示 recovery_required，以未完成恢复处理。start_failed / operation_failed / dependency_error：启动或执行失败的汇总，按前文具体日志排查。
- maintenance_release_failed：维护结束后任务接收未正常恢复。先记录日志并确认没有仍在运行的依赖操作，再重新启动程序检查状态；存在恢复提示时先保留并处理备份。
更新使用与当前程序匹配的完整配套包，设置、Cookie 和下载内容保留。v2.8.0 EXE 与源码版均提供本节入口；旧版请先手动升级主程序与同版本依赖。手动入口：https://github.com/maomaoyexi/video-downloader/releases 。

八、FANBOX 六项修复与版本说明
------------------------------------------------------------
已修复：单任务跨 FANBOX 后，新任务启动成功但停止仍指向旧执行器的问题；失败和取消启动时也不会提前切换路由。

以下六项已随 v2.7.1 正式发布：
1. 排队任务暂停、取消或启动失败后会清理失效活动记录，修正配置后可继续，无需重启；仍有有效租约时拒绝重复启动。
2. 混合 FANBOX 与其他平台的批次在入口被拒绝，请分别创建独立任务；不同任务可并行，归档确认路由到所属执行器。
3. 缩略图与封面按实际资源 URL 确定扩展名，避免 JPEG 缩略图按 PNG/GIF 校验；旧失败资源续跑时可修复错误路径。
4. 预览后的下载允许选择受限帖公开封面，正文与附件权限不变；显式 accessible_only 筛选继续生效。
5. 等待期间每 20 秒续 job、file、asset 租约，异常结束原子保存终态；180 秒等较长间隔本身不再造成租约过期与 running 残留。
6. --fanbox-scan 与 --fanbox-download 均读取保存的 FANBOX_ANONYMOUS、FANBOX_COOKIE_FILE 和 USE_COOKIES；显式 --anonymous 或 --cookies PATH 覆盖本次设置，两者互斥，WebUI 原有行为保持一致。

v2.7.0 旧附件保持原样，仍使用旧版时请按升级说明更新；源码后续调整不自动改变已发布附件。当前正式附件及 SHA-256 见根目录 RELEASE_NOTES.md，历史复现及验证记录见 docs/fanbox-six-fixes-validation.md。

九、排查与反馈
------------------------------------------------------------
1. 记录程序版本、平台、操作入口和首次具体报错；同时查看最终任务结果，不只截最后一行退出码。
2. 检查同一账号在浏览器中是否有原内容的访问权限，再核对相应 Cookie、Firefox 或配置方式。
3. 确认 EXE 和 dependency/ 属同一版本；检查代理、磁盘空间及输出目录权限。
4. 排查格式与自定义参数时先备份设置，再对单条有权限的链接使用兼容配置验证，避免大批量重复重试。
5. 需要反馈时提供报错前后相关日志、任务阶段及是否使用代理/登录；不要发送密码、Cookie 值、访问令牌、完整签名媒体 URL、原始 HAR 或含凭据的配置。
