YT-DLP 多平台视频下载工具 常见问题答疑合集
适配版本：v2.8.1 WebUI（正式版，Windows EXE／源码运行版） | 覆盖平台：YouTube / Bilibili / Twitch / Niconico / NicoChannel / Fantia / TwitCasting / Twitter/X / Rplay / FANBOX
界面方式：浏览器WebUI（双击 video-downloader-v2.8.1-GUI.exe；源码版运行 视频下载工具v2.8.1-GUI.py）
直播录制模式：在「设置 → 直播设置」选择自动、追开播、从当前时刻或蹲开播；默认自动，按平台能力核验后执行。
=====================================
一、启动与运行类
=====================================
问题1：运行Python主程序后浏览器没有自动打开
原因：系统默认浏览器设置问题，或端口被占用
解决：
1、查看控制台窗口显示的端口号（如 http://127.0.0.1:8765）
2、手动在浏览器中输入该地址访问
3、如果端口被占用，程序会自动尝试其他端口

问题2：提示缺少 yt-dlp.exe/ffmpeg.exe/ffprobe.exe
原因：核心依赖文件未放在主程序旁的dependency目录
解决：
1、将对应exe文件放到主程序旁的dependency文件夹
2、缺失时程序会在「关于」页面显示依赖状态和官方下载地址
3、Fantia功能还需额外放置fantiadl.exe（可选）

问题3：运行Python主程序后控制台立即关闭
原因：Python环境不可用、程序模块缺失、依赖文件缺失，或被杀毒软件拦截
解决：
1、确认dependency/yt-dlp.exe、dependency/ffmpeg.exe、dependency/ffprobe.exe存在
2、检查杀毒软件是否隔离了程序文件，添加信任即可
3、确认video_downloader文件夹与Python主程序同目录
4、在命令行中运行「python 视频下载工具v2.8.1-GUI.py」查看具体报错信息
5、源码版同时需要 resource/ 和对应依赖；在项目根目录运行以下命令准备锁定版本的 Python 运行库：
   python scripts/install_live_dependencies.py
   python -m video_downloader.platforms.fanbox.runtime --install
   若直播运行库已存在但版本不符，使用 python scripts/install_live_dependencies.py --upgrade
6、上述命令不安装外部 Bilibili 录播姬和 Withny 受管组件，请完整解压本版依赖包；自行准备时见《使用教程》第一节的官方发布包与项目安装/构建脚本说明

问题4：如何彻底关闭工具？
解决：
1、点击WebUI左侧底部「退出工具」按钮
2、在确认框中点击确定，程序会自动终止所有下载、关闭服务器、退出进程
3、不要直接关闭控制台窗口，可能导致下载进程残留

问题5：关闭浏览器标签页后下载会停止吗？
答：
- 下载进行中关闭页面会弹出确认提示
- 确认关闭后下载继续在后台运行
- 无下载任务时关闭浏览器，30秒后程序自动退出
- 多标签页打开时，关闭其中一个不影响其他标签页

=====================================
二、显示与编码类
=====================================
问题6：日文/中文标题显示乱码
原因：yt-dlp在Windows中文环境下默认编码与浏览器UTF-8不兼容
解决：
- v1.9.3-p4已修复此问题
- 程序自动强制yt-dlp使用UTF-8输出
- 内置多编码回退解码（UTF-8/GBK/Shift_JIS/EUC-JP）
- 如果仍有乱码，请更新到最新版本

问题7：下载进度一直卡在0%不动
原因：链接解析、等待平台响应、未知总量或刚开始音频处理时，暂时显示0%不一定表示卡死。旧版曾有管道缓冲问题，但不能据此判断当前原因。
解决：
- 先查看具体链接的状态、当前阶段与最近日志，区分下载、提取音频和其他后处理
- 「同时输出音频」在视频完成后切换到音频阶段，进度会从0%重新计算
- 若长时间没有新日志或出现具体错误，再按网络、依赖及相应报错排查；旧版本建议先升级
- v2.8.1 在同一文件、同一阶段内保留最高已显示百分比，避免分片总大小重新估算时小幅回退；估算修正时可能暂时停留在原百分比，速度和剩余时间仍实时更新。切换文件、音视频阶段、下一链接或重启下载进程仍会重新计算，不同任务独立。EXE 和源码均包含此修复；原 v2.8.0 附件保持不变。

问题8：直播录制时没有显示已下载大小和速度
原因：Windows管道读取问题（v1.9.3-p3已修复）
解决：
- 更新到最新版本
- 新版重写了输出捕获机制，支持yt-dlp/ffmpeg/分片多种进度格式
- 直播录制实时显示录制时长、已下载大小、下载速度

=====================================
三、停止按钮与进程类
=====================================
问题9：点击停止按钮没反应/下载继续进行
原因：旧版本进程终止和任务状态管理不完善
解决：
- 更新到最新版本
- v1.9.5先设置取消状态，再终止当前yt-dlp/ffmpeg进程树
- 任务使用代际标识隔离迟到回调，旧任务不会覆盖新任务状态
- 停止与进程启动并发发生时，新进程会被拒绝接管并立即清理
- 批量下载停止后不会继续启动后续链接
- v2.7.0 已修复关闭任务模式后跨 FANBOX 切换的停止路由：完成 FANBOX 再成功启动普通视频批量或 Withny 任务，停止和当前命令查询会跟随实际执行器；启动失败、异常或取消选择不会切换路由
- FANBOX 需与其他平台拆成独立任务；不同任务可以并行，当前源码会在入口拒绝混合批次。六项修复与发布状态见第十节

问题10：启动下载后弹出CMD黑窗口
原因：Windows子进程默认分配控制台窗口（v1.9.3-p3已修复）
解决：
- 更新到最新版本
- 新版使用CREATE_NO_WINDOW标志彻底隐藏子进程窗口
- 单一下载和批量下载均已修复

问题11：停止下载后还有残留进程继续上传/下载
原因：未终止整个进程树，ffmpeg等子进程残留（v1.9.3-p3已修复）
解决：
- 更新到最新版本
- 新版使用taskkill /F /T强制终止整个进程树
- 所有异常路径都添加了进程清理逻辑
- 关闭stdout管道唤醒读取线程，确保进程完全退出

=====================================
四、Cookie 报错类（90%用户问题）
=====================================
问题12：Niconico只能下载低画质
原因：未配置登录态Cookie，游客身份仅能获取低清晰度
解决：登录Niconico账号后导出cookies.txt，确认账号本身有对应画质观看权限

问题13：Fantia下载提示权限不足/完全没反应
原因：
1、cookies.txt缺失、命名错误或未在Fantia页面导出
2、账号本身无对应帖子的会员权限
解决：
1、登录Fantia账号后，在fantia.jp页面重新导出Netscape格式Cookie
2、确认账号已订阅对应创作者，可正常浏览目标内容
3、Fantia仅支持cookies.txt文件模式，不支持浏览器提取

问题14：多平台混用，部分平台Cookie不生效
原因：导出Cookie时未访问对应平台，文件内缺少对应域名的Cookie
解决：为使用 Cookie 文件的平台重新导出对应域名的 Netscape 格式 Cookie。Fantia 只支持文件模式；FANBOX 读取专项设置指定的凭据文件（未指定时默认 cookies.txt），匿名访问不使用 Cookie；Rplay 使用独立 Firefox 登录来源，普通 cookies.txt 不能替代。

问题15：Cookie过期了怎么办？
解决：重新在浏览器中登录对应平台，使用Get cookies.txt LOCALLY扩展重新导出即可

=====================================
五、下载失败类报错
=====================================
问题16：subscriber-only content / 需要登录订阅
原因：内容需要登录订阅账号才能观看
解决：导入已订阅/已登录账号的cookies.txt

问题17：Requested format is not available
原因：yt-dlp解析签名失效，或画质设置超出平台上限
解决：
1、在工具箱中点击「更新yt-dlp核心」
2、切换为「通用兼容」预设，降低分辨率上限
3、检查代理是否正常连接

问题18：视频下载一半失败、自动重试
原因：网络波动、分片超时
解决：
1、普通 yt-dlp 下载会按重试设置重试，支持续传的服务器和路径可复用部分文件；Rplay 未完成内容重试时重新下载
2、频繁失败可检查网络代理稳定性
3、程序已添加--socket-timeout 30 --retries 5等参数

问题19：视频合并失败/提示ffmpeg报错
原因：硬件加速模式与显卡不兼容，或视频源损坏
解决：
1、在设置中将硬件加速切换为「CPU软编码」重试
2、更新显卡驱动后再开启硬件加速
3、切换为「兼容优先」编码模式，避免极端编码组合

问题20：Niconico下载超时/连接失败
原因：网络连接不稳定或超时设置过短（v1.9.3-p3已修复）
解决：
- 更新到最新版本，已添加网络超时和重试参数
- 检查代理是否能正常访问Niconico
- URL前后不要有反引号、引号等特殊字符（程序会自动清理）

TwitCasting专项：提示m3u8 HTTP 400或Initialization fragment错误
原因：受限归档登录态/视频密码无效、代理出口被拒绝，或fMP4播放列表中途切换初始化片段
解决：
- 新版会在m3u8 400时受控尝试直连与Firefox登录状态，不会无限重试
- 在Firefox中登录twitcasting.tv；设置为浏览器Cookie模式时，Firefox配置文件名可留空自动探测
- 密码保护内容会弹窗索取密码；不要把账号密码填入视频密码框
- 检测到多初始化片段后会按“下载线程数”并发预取分片，再交给FFmpeg从本地播放列表封装
- 并发预取支持断点缓存：下载成功后自动清理，失败或取消后保留隐藏的.tc-hls缓存供下次重试
- 若并发预取遇到不支持的播放列表，会自动退回原有FFmpeg串行下载，不影响兼容性
- 若仍失败，请关闭代理或更换节点，并重新导出cookies.txt

问题21：提示"You must provide at least one URL"
原因：URL包含反引号、引号等特殊字符导致解析失败（已修复）
解决：
- 新版会自动清理URL前后的反引号、单引号、双引号、空白字符
- 如果仍有问题，手动清除URL前后的特殊字符再粘贴

六、进度显示类问题
=====================================
问题22：Niconico直播进度正常，但其他平台不显示进度
原因：VOD视频被误判为直播流（v1.9.3-p3已修复）
解决：
- 更新到最新版本
- 新版添加了is_live_download标记，只有明确直播才启用直播进度逻辑
- VOD点播使用标准进度解析

问题23：直播状态栏显示重复的录制时长
原因：正则表达式清理不彻底，旧时长未被移除（已修复）
解决：
- 更新到最新版本
- 新版增强正则匹配，添加新时长前彻底移除所有旧时长片段

问题24：下载了20多MB但进度条还是0%
原因：已下载大小与当前阶段百分比不是同一指标；未知总量时不能计算完整百分比，视频完成后开始配套音频也会从0%显示新阶段。
解决：
- 结合阶段名称、速度、日志及输出文件变化判断，不只看百分比
- 「同时输出音频」复用同一进度条显示音频提取进度，不是将音视频进度相加
- 音频提取失败会将该链接记为失败，已成功保存的视频保留；检查 FFmpeg 与具体日志后重试

=====================================
七、功能类疑问
=====================================
问题25：如何防止重复下载？
答：普通视频归档记录统一保存在 download/archive/（*_archive.txt），用于跳过已记入归档的内容；FANBOX 由内容归档单独记录和校验资源。普通 yt-dlp 下载默认启用续传，但取决于服务器和下载路径；Rplay 未完成内容重试时重新下载。归档记录本身不能证明本地文件仍然完整。

问题26：TXT批量下载怎么用？
答：
1、在工具箱中点击「生成链接模板」，会在程序目录生成urls.txt模板
2、用文本编辑器打开urls.txt，每行粘贴一个链接，#开头为注释
3、回到工具箱点击「TXT批量下载」，程序自动识别平台并批量下载
4、任务模式下创建队列任务，任务间及任务内按并发设置运行；关闭任务模式后，旧单任务模式按链接顺序串行处理，可查看当前/总数及成功/失败统计
5、取消任务会停止其活跃链接并阻止后续链接继续启动；顶部停止按钮取消全部活跃任务
6、FANBOX 请用独立 TXT 文件或单独提交，不与其他平台混在同一任务；不同任务仍可并行

问题27：直播链接无法录制？
答：先确认直播仍在进行且账号有权限，再检查链接入口：YouTube 使用 /live 或 /live/；Bilibili 使用 live.bilibili.com/房间号；Twitch 使用主播频道页；Niconico 使用 live.nicovideo.jp、live2.nicovideo.jp 或 /watch/lv...；NicoChannel 使用 nicochannel.jp/频道/live/...；TwitCasting 使用主播页；Twitter/X Spaces 使用 x.com/i/spaces/...。选择「追开播」时，如果平台没有 DVR/Timeshift，程序会自动改为从当前分片录制。必要时配置 Cookie、Firefox 登录令牌或更新 yt-dlp 核心。已结束直播只有平台保留回放时才能下载。
补充：v2.8.0 正式 EXE 若在 Bilibili 预检查时报「网络错误: [Errno 2] No such file or directory」，已确认是 SSL 证书策略资源漏包，不是未登录。v2.8.1 主程序已补齐原策略资源并增加默认 TLS 初始化自检；请升级主程序。无需清空配置或反复更换 Cookie；外置依赖更新不能补齐旧 EXE 内嵌文件。

问题28：配置预设怎么用？
答：
1、在设置页面调整好所有参数
2、点击设置顶部的「💾 保存」按钮，输入预设名称
3、需要时从下拉框选择预设，立即加载所有配置
4、不需要的预设可点击「🗑 删除」按钮删除
5、预设集成在设置页面顶部，不再有独立标签页

问题29：临时文件会自动清理吗？
答：可以在工具箱中点击「清理临时文件」手动清理。.part 保存下载中的媒体数据，.ytdl 保存分片恢复信息，不是可以改名播放的视频；是否可续传取决于平台与路径。未完成任务清理后会丢失相应续传数据，请确认后再操作。

问题30：如何更新yt-dlp核心？
答：进入工具箱，点击「更新yt-dlp核心」按钮，一键自动更新到最新版

问题31：设置错了想恢复默认怎么办？
答：在设置页面底部点击「恢复默认设置」按钮，一键恢复所有参数到默认值

问题32：下载历史保存在哪里？
答：历史记录保存在download/download_history.json，在「历史」标签页可查看最近500条记录，支持一键清空

问题33：WAV转MP3工具怎么用？
答：
1、进入工具箱，点击「WAV转MP3」
2、选择要转换的文件夹或单个WAV文件
3、选择MP3比特率（推荐320kbps）
4、可选是否递归子目录、转换后删除源文件
5、点击开始转换，转换完成显示统计

问题34：录制的直播文件保存在哪里？
答：
- YouTube直播：download/YouTube/上传者名/直播/ 目录
- Twitch直播：download/Twitch/主播名/直播/ 目录
- Niconico直播：download/Niconico/直播/ 目录
- 文件名包含主播名、录制时间、直播ID等信息

问题35：YouTube直播支持吗？
答：支持。程序会识别YouTube的/live或/live/形式链接，并按本分支的自动、条件追开播、从当前时刻或蹲开播模式执行；录制过程中显示录制时长、大小、分片或速度信息

问题：TwitCasting 录播密码会记住吗？
答：默认不保存。设置 → 平台专项 → TwitCasting 的“记住密码”用于本次运行内按链接复用；同时开启“保存密码到 XLSX”后，才读写根目录 twitcasting_passwords.xlsx 并迁移旧表。两项均默认关闭，密码表以明文保存密码，除非获得明确授权，请勿发送给其他人。关闭不删除已存在的表格。失效密码会在对应任务内重新询问。

问题36：各平台直播录制文件保存在哪里？
答：文件按平台和主播自动分类，通常位于 download/<平台>/<主播或频道>/直播/。Niconico 的直播目录可能直接使用 download/Niconico/直播/；Twitter/X Spaces 通常保存到 download/Twitter/直播/。Withny 通过受管会话接管输出与部分录制选项，不能仅按原 config.yaml 中的输出路径查找；以任务记录和 download/.live-jobs/<job-id>/ 下当前会话的报告为准，详见 withny_har_guide.txt。

问题37：下载封面会生成什么文件？
答：开启「下载封面」后会写出并转换为JPG；合并输出、非WebM且未启用分离音频时还会尝试嵌入媒体文件，其他模式为避免后处理冲突不会嵌图
也可在工具箱使用「下载视频封面」，输入多行链接仅保存JPG图片，沿用当前视频输出目录和命名规则，不写入下载归档。Fantia、Withny及未识别平台暂不支持此工具。

问题38：一键更新为什么提示缺少SHA-256或来源不可信？
答：v1.9.5的安全更新要求可信HTTPS来源、最大512MB、有效SHA-256，并核对下载大小和Windows EXE格式；任一校验不通过都会拒绝替换。源码运行版请同时更新主脚本、video_downloader/、resource/ 和对应依赖。
自动检查、下载或校验失败时，更新弹窗提供「前往 GitHub 手动更新」：https://github.com/maomaoyexi/video-downloader/releases/latest 。关闭旧程序后，按发布页说明下载新版 EXE 和配套依赖包，保留设置、Cookie 与 download/。若程序已经退出，在替换或重启阶段失败，会打开包含同一链接的本地错误说明。源码中的这项提示须在重新打包后才会进入新的 EXE，已发布旧附件不会自动改变。

问题39：提示已下载时，如何选择重新下载？
答：命中归档后会弹窗询问「重新下载」或「跳过」，20秒未选择默认跳过。跳过单独计数，不算下载成功。选择重下只清理本次命中的归档记录，并按当前模板覆盖同名视频和配套音频，不生成编号副本；其他归档记录保留。若更改输出目录、模板或格式，新文件按新设置保存；归档本身不能证明旧文件仍然完整。

问题40：YouTube PO Token 首次启动看起来没有下载，可以停止吗？
答：Provider 在后台准备，日志每5秒报告等待进度，最多等待60秒，健康检查通过后才开始下载。准备期间可点击「停止」。启动失败会保留Deno错误并释放任务；请按日志补齐依赖后重试。程序不会在线安装Provider依赖，也不会等待控制台交互确认。

九、v2.7.0 新增平台与升级
=====================================
问题41：正式版需要下载哪些文件？
答：只需 video-downloader-v2.8.1-GUI.exe 和 video-downloader-v2.8.1-dependencies.zip。EXE 无需安装 Python，把完整 dependency 文件夹解压到 EXE 同目录即可。依赖包已含 NicoChannel 插件，不需另下 nicochannel.zip。升级前退出旧程序，保留设置、Cookie、密码表和 download/。

问题42：Rplay 已经有 cookies.txt，为什么仍提示登录？
答：Rplay 使用独立 Firefox 登录来源，不能以普通 cookies.txt 替代。请先在 Firefox 登录，再在设置中选择 Rplay 登录来源与配置。账号仍须拥有目标内容权限；DRM、未知加密和未接入授权协议不在支持范围内。

问题43：Rplay 支持哪些链接？Twitch 转播也能下载吗？
答：单个 /play/<内容ID> 为点播，/live/<创作者ID> 和 /creatorhome/<创作者ID> 为直播入口。平台返回 Twitch 转播状态时通过 Twitch 提取器解析源频道，源频道须仍在直播且可访问。实现接入不代表所有账号与直播源均已实测；HLS 暂不支持分离音画。

问题44：FANBOX 预览、扫描和下载有什么区别？
答：预览先抓取帖子并供筛选；--fanbox-scan 只写清单，不下载附件；--fanbox-download 或 WebUI 下载所选会执行内容归档。可保存正文、JSON、可访问图片附件、封面、链接及可选评论，也支持粉丝卡。受限帖公开封面不代表正文可访问；外链只收集，不自动下载外部内容。

问题45：FANBOX 的粉丝卡、文件复用和校验能保证完整吗？
答：不能仅凭功能开关或父任务成功状态判断完整。结果取决于账号权限、平台返回和筛选条件，请查看归档清单、具体资源状态及校验报告。粉丝卡和评论可能不可用；当前源码已修复缩略图扩展名误配和预览后遗漏公开封面，受限正文和附件仍按实际权限处理。

问题46：能同时运行多个任务并分别看日志吗？
答：任务模式默认开启，任务间默认并行 2 个、可设 1–5；任务内直播与视频使用独立额度。FANBOX 请独立建任务，不与其他平台混在同一任务；不同任务仍可并行。点击任务行查看具体链接、进度、历史和独立日志。普通队列重启后不恢复；持久化蹲开播由等待开播面板管理。带宽有限时降低并发并使用限速。

问题47：直播弹幕为什么缺失或时间不完全一致？
答：评论采集能力、登录权限、源平台时间和录制起点不同。程序提供 SRT/ASS 与 comments-report.json，请核对报告，不能把接入某个平台理解成该平台所有直播已验证或精确同步。原始评论文件可能含账号信息，公开反馈前请检查。

十、FANBOX 六项修复与版本说明
=====================================
单任务跨平台切换后的停止路由已在 v2.7.0 修复，详见问题9。以下六项已随 v2.7.1 正式发布；v2.7.0 的旧附件保持原样，仍使用旧版时请按升级说明更新。

1. 排队任务取消或启动失败：失效活动记录会清理，归档转为可继续状态；修正启动配置后可继续，无需重启程序。
2. 与其他平台混合批量：入口拒绝混合输入，请将 FANBOX 单独创建任务；不同任务可并行，归档确认路由到所属执行器。
3. 缩略图与封面格式：按实际资源 URL 确定扩展名；旧失败资源续跑时可修复扩展名与路径不一致，无需因该问题改用原图质量。
4. 预览后下载：可选择受限帖公开封面；正文和附件仍按权限处理，显式 accessible_only 筛选继续排除受限帖。
5. 较长请求间隔：等待期间每 20 秒续 job、file、asset 租约，异常结束时原子保存终态；180 秒间隔本身不会再导致租约过期并残留 running。
6. 独立扫描 CLI：--fanbox-scan 与 --fanbox-download 均读取保存的 FANBOX_ANONYMOUS、FANBOX_COOKIE_FILE 和 USE_COOKIES；显式 --anonymous 或 --cookies PATH 可覆盖本次设置，且不能同时指定。WebUI 原有行为保持一致。

发布附件与 SHA-256 见根目录 RELEASE_NOTES.md；源码后续调整不自动改变已发布附件。六项修复的历史复现及验证记录见 docs/fanbox-six-fixes-validation.md，任务是否完整仍需核对具体资源、日志与归档清单。

=====================================
十一、依赖检测与更新（v2.8.0 新增）
=====================================
问题48：依赖会自动检测或下载吗？
答：当前源码在启动或打开「关于软件 → 依赖状态 → 更新依赖」时只检测文件是否缺失，不自动下载、不做全目录哈希检查。需要补齐或更新时点击「更新依赖」并确认一次，下载与当前程序匹配的官方完整配套包，校验后备份并替换外置组件。文件存在不等于内容或平台兼容性已经验证，详细步骤见《使用教程》第一节。

问题49：我自己更新过 yt-dlp，会被还原吗？
答：默认保留自行升级的 yt-dlp，其兼容性仍需实际任务验证；其他外置组件会在确认依赖更新后先备份再替换。配置、Cookie、下载内容保留。

问题50：更新依赖能同时修复 Python 运行库吗？
答：Python 运行库只读，避免在运行中替换已经加载的 Python 或原生库。EXE 所需库随主程序维护；源码环境请关闭程序后，按《使用教程》第一节或 README 的锁定版本命令准备对应运行库。更新外置工具不能替代源码 Python 环境准备。

问题51：依赖更新使用哪个版本的包，会升级主程序吗？
答：只使用与当前程序匹配的官方完整配套包，不会因此升级主程序。需要升级程序时，按发布页说明更新 EXE 或源码，再检查对应依赖。这项能力从 v2.8.0 开始提供；旧版没有入口时先手动更新主程序与同版本依赖。

问题52：安装时提示任务占用，或取消后为什么还在等待？
答：先完成或取消下载、队列、音频工具和监控任务；依赖维护期间会阻止新任务启动。取消或失败后需等待当前读取结束和必要的备份恢复；提示 recovery_required 时保留 download/.dependency-manager/，按界面继续更新以恢复，恢复完成前不能开始下载。有未完成维护时先在原版本完成恢复再升级；已升级遇清单不兼容、备份损坏或文件又被修改时，保留备份，回原版本恢复或人工处理，不要删除现场。

问题53：依赖检查或下载失败怎么办？
答：先按具体错误检查网络、文件权限、空间及变化项；使用界面的「前往 GitHub 手动下载依赖」，或访问项目官方发布页 https://github.com/maomaoyexi/video-downloader/releases ，按对应版本说明补齐 EXE 和配套依赖。不要绕过 SHA-256 或来源校验，也不要删除配置、Cookie、下载数据或尚待恢复的备份。错误码和状态说明见《错误码》中的依赖检测与更新段。

问题54：点击「更新依赖」没有反应，怎么办？
答：先确认页面地址与当前程序控制台显示的 WebUI 地址一致，刷新当前页面后再尝试。区分「依赖检测与更新」窗口完全没打开，还是窗口已经打开但内部检测或更新失败；后者按具体提示和问题53处理。窗口未打开不表示已开始更新，不要连续盲点更新，也不要删除 dependency/、配置或下载数据。
若仍无响应，记录页面 URL、程序版本及源码／EXE 运行方式、操作步骤、是否出现窗口，以及相关控制台和程序日志，反馈前遮盖凭据等敏感信息。偶尔重启后恢复也只是排查线索，不代表已确认唯一原因，重启不是每次必做步骤。当前源码已调整入口初始化时序，已发布 EXE 不会因此自动改变。

问题55：关闭代理开关后，程序所有请求都会直连吗？
答：不是全程序总开关。常规 yt-dlp 下载和 FANBOX 关闭后默认按直连处理；更新检查、程序和依赖更新、部分探测及 B站分P读取仍可能沿用系统／环境代理。默认或本次参数里的 --proxy 可以覆盖按钮设置；TUN／VPN 属于系统网络层。判断实际出口应结合本次命令和网络情况，不要只看按钮或浏览器是否能打开网站。

=====================================
十二、启动器与临时目录
=====================================
问题56：下载报 4294967295，为什么别人正常，重试后又好了？
答：4294967295 按 32 位有符号整数解释为 -1，不是 HTTP 429，也不能单独证明 B站限流、Cookie 失效或临时目录故障。
若前文明确出现「[PYI-...:ERROR] Could not create temporary directory」，表示该进程的启动器无法创建解包用临时目录。先检查 TEMP/TMP 可写性、相关磁盘空间及实际拦截记录，完整步骤见《错误码》第四节。
重试恢复只说明当前已恢复，具体触发原因仍未确认，不能因此认定程序已修复或该用户操作错误；持续失败再保留首条错误与发生时间排查。不要把它与问题27中的 v2.8.0 EXE SSL 漏包问题混为一谈。
