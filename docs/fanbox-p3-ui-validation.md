# FANBOX P3：设置、任务交互与历史验收

日期：2026-10-31，当前 main 分支。未修改 README。承接 P2 的原生下载器、成功索引和调度器，本阶段完成 WebUI 与新增实用选项的执行对接。

## 交付行为

- 主操作区按“停止、预览、抓取并下载”排列；删除下方重复的预览/归档设置入口。普通视频流程保持原入口。
- 平台专项中的 TwitCasting 使用完整的设置名称，不再单设分割标题。FANBOX 使用轻分隔，每个设置一行；开关 32×18、普通输入 34 像素高，使用项目原有明暗主题令牌。
- 全局默认值与本次任务共享一套表单生成器。点击下载先克隆默认值，确认后将覆盖值写入任务快照；取消不创建任务，也不写回全局。纯 FANBOX 多链接使用同一份本次设置、逐链接独立请求标识，重试不会重复创建已接受任务。
- 设置涵盖正文与导出格式、原始 JSON、封面、评论及页数、外链清单、图片质量/降级、免费/付费、金额比较与闭区间、投稿 ID、日期闭区间、资源类型、标题/附件名称关键词、目录/命名模板与收藏、补零、文件冲突、并发/间隔/代理、增量复用、日额度/时区/次日继续、完成通知及关键词高亮。
- 粉丝卡提供启用、仅下载粉丝卡、当前/全部赞助作者和是否显示用户名。读取真实赞助 API，沿用附件下载器的域限制、调度、取消及额度计量；独立绘制 1280×800 PNG。没有复制插件的遮罩或品牌图片，外观使用独立排版。用户名不进入文件名、任务摘要或日志。赞助列表为空时记录粉丝卡失败并继续保存可访问帖子，结果为部分完成；仅粉丝卡任务则明确失败。
- 主运行日志在 FANBOX 与视频模式之间切换缓存；FANBOX 日志记录列表页、投稿权限、文件数、复用/失败/降级、粉丝卡、暂停与结束统计，遵循参考插件的任务用语。单任务持久化最近 500 条，按任务及序号消除重放重复；界面显示最多 300 条。
- 下载历史对 FANBOX 按规范来源链接去重，进入详情窗口后可切换该链接的运行记录，分页筛选帖子、按需展开正文/评论/文件/外链，查看实际文件状态及路径。历史窗口隐藏选择下载控件；任务预览窗口支持选择帖子和附件。不会把 HTML 归档当视频封面请求。
- 鉴权状态区分“凭据已载入”与真实内容权限，不以本地有 Cookie 证明已赞助。没有设置导入入口；旧兼容 API 保留。

## 实现与可靠性

`controller` 负责鉴权后的命令/查询与安全投影，`archive` 编排归档，`service` 负责抓取，`fan_cards` 负责独立图片生成，视频执行器继续通过路由门面组合。WebUI 不嵌入来源 HTML，不暴露二进制签名 URL；需要本地会话令牌，保留 Host/Origin 与请求体限制。

SQLite schema 1 升级到 2 时先保存数据库备份，再增加持久化幂等请求记录。任务动作检查版本及运行租约；恢复沿用任务冻结值，不读取后来改变的全局默认值。崩溃后的任务标为中断，只有用户明确设置的次日额度策略会定时继续。

修复截图中的异常：`HTMLTextAreaElement.type` 是只读属性，表单现在只给 input 设置 type。另通过真实浏览器发现通用按钮/标签样式会覆盖 hidden 的默认样式，已给弹窗补充明确隐藏规则，确保历史窗口实际只读。

Pillow 12.2.0 从官方 PyPI 元数据锁定 wheel 哈希；安装使用 `--require-hashes --only-binary`。图片解码限制 2400 万像素，异常背景不会冒充成功；PNG 使用临时文件原子替换。源运行依赖和许可证已补齐，构建 spec 收集 PIL 动态模块及原生库。

## 验证结果

- 最终全项目回归：983 项通过、1 项跳过，另有 51 项子测试通过。跳过的是原有默认关闭的长时间直播中断测试。FANBOX 语句与分支综合覆盖率 90.98%。
- DOM 集成：设置组完整渲染、多行文本、按钮位置、弹窗默认值/隔离/取消、日志切换/去重、按链接历史及安全文本渲染通过。
- 独立无头 Edge：完整页面初始化、本次金额覆盖值、全局默认值不变、历史窗口、实际控件尺寸、逐行布局通过；明/暗主题 × 320/768/1440 像素六种组合无设置或弹窗横向溢出，没有 JavaScript 错误。测试使用合成数据和全新浏览器配置，没有连接用户 Chrome。
- 真实授权数据：kanibiimu 单帖按实际日期和金额做闭区间筛选，预览后只下载选定原图；完整解码后的宽高与 API 一致，复跑确认复用。提高最低赞助金额后候选帖子归零。不是全作者归档验收。
- 现有 Cookie 包含有效格式的会话，shirohanemu、kanibiimu 付费正文实际可访问；但当前赞助列表为空，mimoriaino、shirohanemu、kanibiimu 粉丝卡接口均返回 404。因此真实粉丝卡保存未获成功样本；图片生成、背景传输、匿名开关、仅粉丝卡流程和不可用状态由合成协议测试覆盖，不能替代真实成功验证。
- 使用临时干净 Python 3.12 环境及项目完整 spec 构建主程序成功；完整 EXE 的现有 8 项直播依赖自检全部通过，CLI 启动正常，冻结程序真实授权单帖抓取完成。最终冻结程序的原生归档实际保存了授权正文/链接，同时正确报告粉丝卡不可用的部分完成状态。包内核对 PIL 绘图/字体模块、原生解码器及许可证，并确认 FANBOX 脚本字节与最终源码一致；没有以简化测试入口冒充主程序验证。冻结后的粉丝卡生成仍缺少真实可用赞助卡样本。

浏览器回归保留在 `tests/web/fanbox_ui.test.mjs`、`tests/web/fanbox_browser.test.mjs`。测试依赖为临时安装的 happy-dom 20.8.4、Playwright 1.58.2，支持环境变量指定模块或浏览器路径；不增加应用运行依赖。已删除验收图片、真实原图/正文/检查点、测试数据库、测试工具、npm 缓存、构建环境和 EXE；保留正式运行依赖、维护的回归测试、用户计划及参考插件。

复现前端验证：将上述两个 npm 包安装到 `temp/fanbox-ui-qa` 后执行 `node --test tests/web/fanbox_ui.test.mjs tests/web/fanbox_browser.test.mjs`；浏览器测试默认使用 Windows Edge，无头模式使用独立临时配置。
