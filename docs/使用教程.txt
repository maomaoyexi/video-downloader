YT-DLP 多平台视频下载工具 完整使用教程
适配版本：v2.7.1 WebUI（开发版）（Windows EXE／源码运行版）
支持平台：YouTube / Bilibili / Twitch / Niconico / NicoChannel / Fantia / TwitCasting / Twitter / Rplay / FANBOX
特殊功能：Withny 已授权历史存档 HAR 保存与直播监控；FANBOX 扫描、预览和内容归档
界面方式：浏览器WebUI（运行 Windows EXE 或 Python 主程序后自动打开浏览器）
=====================================
一、安装与依赖说明
=====================================
以下为 v2.7.0 安装包的文件命名；可下载版本以 GitHub Releases 实际发布内容为准：
  1. video-downloader-v2.7.1-GUI.exe
  2. video-downloader-v2.7.1-dependencies.zip

安装步骤（Windows EXE 绿色版）：
  1. 新建单独文件夹，将 EXE 放入其中，无需安装 Python
  2. 将依赖包中的 dependency 文件夹完整解压到 EXE 同一目录
  3. 双击 video-downloader-v2.7.1-GUI.exe，浏览器自动打开 WebUI
  4. 按需要配置 Cookie、代理；Rplay 登录使用独立 Firefox 设置

升级步骤（老用户）：
  1. 点击右上角「✕ 退出」关闭旧版本，等待下载与录制结束
  2. 替换新版 EXE，并完整更新 dependency 文件夹
  3. 保留 settings.ini、presets.json、cookies.txt、download/ 和原有密码表
  4. 配置与下载历史继续兼容，不需要清空归档或重新下载已有内容

源码运行方式（仓库源码，不另发源码附件）：
  1. 安装 Python 3，并确保 python 命令可用
  2. 保持 视频下载工具v2.7.1-GUI.py、video_downloader/、resource/ 和 dependency/ 位于同一目录
  3. 在项目根目录准备锁定版本的直播与 FANBOX Python 运行库：
     python scripts/install_live_dependencies.py
     python -m video_downloader.platforms.fanbox.runtime --install
     直播运行库已存在且锁定版本有变化时，使用 python scripts/install_live_dependencies.py --upgrade
  4. 运行：python ".\视频下载工具v2.7.1-GUI.py"
  5. 升级源码时同时更新主脚本、video_downloader/、resource/ 和对应依赖，保留个人配置与下载目录

依赖说明：
  - 基础工具为 dependency/yt-dlp.exe、ffmpeg.exe、ffprobe.exe、deno.exe
  - 依赖包还包括 Fantia、Withny 工具、NicoChannel 插件 nicochannel.zip、Rplay 插件及本版所需运行依赖
  - dependency 文件夹须与主程序同目录，不要只更新其中一个工具而漏掉平台插件
  - 上述 Python 运行库准备命令不会安装外部录制组件；Bilibili 录播姬与 Withny 受管组件请使用本版完整配套依赖包
  - 自行准备源码依赖时，可用官方 BililiveRecorder 2.20.0 win-x64 发布包运行 python scripts/install_bililive.py "官方压缩包路径"；Withny 可运行 python scripts/build_withny_dependency.py（需要 Go 1.25 或更新版本）。脚本会校验来源内容并生成配套 manifest，不要只复制一个 EXE
  - 各平台所需依赖和账号权限不同，请在「关于」页面检查状态，再用少量链接确认输出

=====================================
二、首次运行须知
=====================================
本工具仅用于个人学习研究，禁止商用、侵权传播下载内容。

双击 video-downloader-v2.7.1-GUI.exe 启动；源码版运行「python 视频下载工具v2.7.1-GUI.py」。
程序会自动启动内置HTTP服务器，并调用系统默认浏览器打开WebUI界面。
首次运行自动生成各平台保存目录、配置文件settings.ini、历史记录文件。
所有下载自动按【平台 / UP主 / 主播 / 创作者文件夹】分类整理。

重要提示：
- 使用过程中不要关闭Python控制台窗口（它是后端服务器）
- 有任务时关闭网页，确认后任务继续在后台运行；无任务时关闭网页，程序会在 30 秒后退出
- 需要彻底关闭工具时，点击界面右上角红色「✕ 退出」按钮

=====================================
四、基本下载操作
=====================================
1. 单视频下载
   - 进入「下载」标签页
   - 在输入框中粘贴视频链接
   - 确认平台选择正确（可自动识别）
   - 点击「开始下载」按钮
   - 实时查看进度条、下载速度、已下载大小、剩余时间

2. 播放列表/频道下载
   - 直接粘贴播放列表或频道链接
   - 程序会自动识别并列出内容
   - 支持选择全部或指定集数下载

3. 停止下载
   - 下载过程中点击「停止下载」按钮
   - 程序会先登记取消状态，再安全终止yt-dlp/ffmpeg进程树
   - 任务代际隔离可阻止旧任务的迟到进度覆盖新任务状态
   - 停止请求与子进程启动发生在同一时刻时，新进程也会被拒绝接管并立即清理
   - 支持续传的下载会保留部分文件供重试；具体限制见第十二节，Rplay 未完成内容重新下载

4. Withny 历史存档
   - 在下载页面的平台栏选择 Withny
   - 点击「选择 HAR 并下载」
   - 依次选择浏览器导出的包含内容 HAR 和输出位置
   - 仅处理已授权的普通未加密 HLS，DRM 或加密内容会被拒绝
   - HAR 可能包含登录信息，下载完成后立即删除
   - 详细步骤见 docs/withny_har_guide.txt

=====================================
五、自动更新功能
=====================================
程序支持自动检查更新和一键更新：

- 启动后3秒自动静默检查更新，有新版本时右上角显示「⬆ 有更新」徽标
- 点击徽标查看新版本信息，点击「一键更新」自动下载并替换
- 统一通过 GitHub Releases 检查和分发最新版本
- 仅接受可信HTTPS来源，更新文件最大限制为512MB
- 发布信息必须提供有效SHA-256；下载后还会核对文件大小、SHA-256和Windows EXE格式
- 源码运行状态不会用EXE覆盖Python主程序；升级源码时请同时更新主脚本、video_downloader/、resource/ 和对应依赖
- 自动替换重启仅适用于打包后的Windows EXE运行版
- 也可在「关于」页面查看当前版本号

=====================================
六、画质与输出设置（设置页面）
=====================================
进入「设置」标签页，可配置以下选项：

  分辨率上限：无限制 / 4K / 2K / 1080P / 720P / 480P / 360P
  编码模式：极致画质 / 兼容优先(H.264) / AV1优先 / VP9优先
  音频模式：最高音质 / 均衡(192k) / 最小体积(128k)
  输出格式：MP4 / MKV / WebM
  分离音频格式：m4a(原生) / MP3 / FLAC / WAV
  网络代理配置（HTTP / SOCKS5）
  FFmpeg硬件加速：CPU软编码 / N卡NVENC / Intel QSV / AMD AMF
  浏览器Cookie来源：Chrome / Edge / Firefox / Brave / Opera / cookies.txt文件
  Niconico弹幕下载开关
  YouTube PO Token开关：下载YouTube前自动启动本地BgUtils Provider
  默认yt-dlp参数：保存后自动附加到每次yt-dlp下载命令
  文件名兼容、元数据嵌入、下载封面等开关

下载页面另有「本次 yt-dlp 参数」输入框：
  - 对当前单条、多行批量或TXT批量任务有效，启动成功后自动清空
  - 不会写入settings.ini
  - 含空格的参数值请使用英文双引号包裹

YouTube PO Token依赖：
  - dependency/deno.exe
  - dependency/yt-dlp-plugins/bgutil-ytdlp-pot-provider.zip
  - dependency/bgutil-ytdlp-pot-provider/server/src/main.ts
  - dependency/bgutil-ytdlp-pot-provider/server/node_modules
开启后无需手动运行CMD。程序会检查127.0.0.1或IPv6本机回环地址的4416端口，
复用已运行的Provider，或自动启动并等待/ping成功后再调用yt-dlp获取PO Token。
首次启动在后台准备，日志每5秒报告进度，最多等待60秒，期间可点击「停止」。
失败时会记录Deno错误并释放任务，修复依赖后可重试；启动不会在线安装依赖或等待控制台确认。
下载归档命中时，可在弹窗选择「重新下载」或「跳过」，20秒未选择后自动跳过并继续队列。
跳过单独计数，不视为下载成功。重下仅清除命中的归档记录，覆盖同输出路径的视频和配套音频，
不生成编号副本；其他归档记录保留。更改输出目录、模板或格式后，会按新设置保存文件。
PO Token只能缓解部分YouTube 403或机器人校验，仍可能需要有效Cookie或更换网络出口。

封面说明：
  - 「下载封面」默认开启，会写出并转换为JPG封面
  - 合并输出且格式不是WebM、未启用分离音频时，会同时尝试将封面嵌入媒体文件
  - WebM、分离音频或独立音视频下载时不嵌入封面，以避免后处理冲突

配置修改后点击「💾 保存设置」按钮生效。

=====================================
九、Cookie 登录配置（最重要）
=====================================
大多数原有平台和 FANBOX 推荐使用 cookies.txt 文件模式；Rplay 使用独立 Firefox 登录设置，步骤见第十七节。Cookie 配置步骤：

1. Edge/Chrome/Firefox 安装扩展：Get cookies.txt LOCALLY
   （纯本地运行，不会上传Cookie数据）
2. 打开对应平台官网，登录你的账号；多平台使用可依次登录所有平台
3. 在目标平台页面打开扩展 → 导出 Netscape 格式 cookies
4. 导出文件命名为：cookies.txt
5. 放到程序同级目录（与 视频下载工具v2.7.1-GUI.py 同目录）

支持浏览器提取的平台也可在设置页面选择浏览器 Cookie 来源（Chrome/Edge/Firefox 等）。Fantia 仅支持 cookies.txt 文件；FANBOX 使用专项设置指定的 Netscape Cookie 文件（未指定时默认 cookies.txt），匿名访问不使用 Cookie；Rplay 使用独立 Firefox 登录来源。

适用场景：
  YouTube 会员专属、年龄限制、受限内容
  Twitch 订阅专属、会员内容
  Niconico 720P及以上画质、会员内容
  Fantia 登录可见、付费会员帖子（Fantia仅支持cookies.txt文件模式）

详细Cookie配置说明请参考「docs/cookies问题答疑.txt」。

=====================================
十、直播录制使用方法
=====================================
当前修复源码的「设置 → 直播设置」按录制方式、稳定性与资源、弹幕设置分组，配置值仍通过页面右上角「保存设置」保存。
需要单独覆盖平台时，展开「各平台录制方式」或「各平台弹幕默认值」；长机制说明在对应「说明」内展开查看。

YouTube直播录制：
  1. 粘贴YouTube的/live或/live/形式直播链接
  2. 在「设置 → 直播设置」选择全局/平台默认直播模式
  3. 开始前会检查直播状态；已开播会显示开播时间与已开播时长
  4. 未开播时可按提示选择蹲开播，开播后自动开始录制
  5. 追开播不可用时会提示原因并降级为从当前时刻
  6. 录制过程中显示录制时长、已下载大小、分片或速度信息
  7. 文件保存到 download/YouTube/上传者名/直播/ 目录

Twitch直播录制：
  1. 粘贴主播频道链接（如 https://www.twitch.tv/主播名）
     注意：必须是主播频道主页，不是具体视频/剪辑页面
  2. 自动模式下尝试追开播，但只有本场存在可访问的增长中 VOD 时才可能从头
  3. 未开播时会提示是否加入蹲开播，不会静默无限等待
  4. 录制过程中实时显示录制时长、已下载大小、下载速度
  5. 点击「停止下载」结束录制，或主播下播后自动结束
  6. 文件自动保存到 download/Twitch/主播名/直播/ 目录

Niconico直播录制：
  1. 粘贴Niconico直播链接（live.nicovideo.jp 或 live2.nicovideo.jp）
  2. Niconico当前只从当前时刻录制（上游chasePlay固定关闭）
  3. 实时显示录制进度；点击「停止下载」结束

Bilibili直播录制：
  1. 粘贴 live.bilibili.com/房间号
  2. 从当前时刻录制；普通观看侧无DVR，不支持追开播
  3. 文件保存到 download/Bilibili/上传者名/直播/ 目录

TwitCasting直播录制：
  1. 粘贴主播页链接，默认从当前时刻录制（平台不支持yt-dlp从头）
  2. 会员追っかけ不在当前版本支持范围内

十一、下载历史记录
=====================================
进入「历史」标签页查看下载记录：
  - 自动记录每次下载的详细信息：时间、平台、视频标题、URL、状态
  - 彩色标签区分平台：YouTube(红)/Twitch(紫)/Niconico(蓝)/Fantia(粉)

  - 历史数据保存在 download/download_history.json

=====================================
十二、断点续传说明
=====================================
普通 yt-dlp 下载默认使用 --continue；能否续传取决于平台、服务器和下载路径：
  - 支持续传时，网络中断或手动停止后可重新提交同一 URL，复用保留的部分文件
  - Rplay 当前禁用断点续传，未完成内容重试时重新下载；直播录制和其他专用下载路径也不能统一保证续传
  - 配合下载归档记录机制，可跳过已经完成并记入归档的内容；归档记录本身不能证明文件仍然完整
  - .part 是下载中的媒体数据，成功后按下载器规则生成最终文件；.ytdl 是分片恢复信息，不是可改名播放的视频
  - 清理未完成任务的临时文件会丢失相应续传数据，请确认后再清理

=====================================
十三、文件保存规则
=====================================
自动分类：程序目录 / download / 平台名 / UP主/主播/创作者名 / 视频文件；FANBOX 默认使用 download/Fanbox/
自动去重：普通视频归档记录位于 download/archive/（*_archive.txt），可跳过已记入归档的内容；FANBOX 在「内容归档」中单独记录与校验
临时文件：支持的路径可利用 .part 媒体数据和 .ytdl 恢复信息续传，具体限制见第十二节
日志记录：控制台实时输出日志，WebUI界面实时显示

=====================================
十四、退出与关闭说明
=====================================
彻底关闭工具：
  点击界面右上角红色「✕ 退出」按钮 → 确认退出
  程序会：终止正在进行的下载 → 关闭HTTP服务器 → 退出进程
  页面显示「工具已关闭」提示，可安全关闭浏览器

关闭浏览器标签页：
  - 下载进行中关闭：弹出确认提示，下载继续在后台运行
  - 无下载任务时关闭：30秒后自动退出进程
  - 多标签页打开：关闭其中一个不影响其他标签页

=====================================
十五、最佳稳定配置（推荐）
=====================================
Cookie模式：大多数平台使用 cookies.txt；Rplay 使用独立 Firefox 登录设置
画质预设：通用兼容（日常播放最稳）/ 最高画质（收藏用）自选
输出格式：MP4
音视频模式：合并输出
编码：兼容优先（H.264，所有设备可直接播放）
代理：根据网络环境配置
下载限速：推荐 5–10 MB/s。高速或大批量下载可能导致 IP 或账号被限制或封禁，相关后果由使用者自行承担
运行方式：完整保留 dependency 目录及其子目录；源码版先按第一节准备运行库，再运行「python 视频下载工具v2.7.1-GUI.py」
关闭方式：使用「✕ 退出」按钮彻底关闭，不要直接关控制台窗口

=====================================
十六、任务模式（多任务并行）
=====================================
1. 在「设置 → 任务与并发」开启任务模式（默认开启）
2. 每次点击「开始」创建一个任务，显示在链接输入框下方
3. 任务行按进度填充颜色；点击展开可查看链接、状态、历史、日志
4. 任务行右侧「取消」可单独停止；顶部停止按钮取消全部活跃任务
5. 「最大并行任务数」默认 2、可设 1–5；1 为任务间串行；并行任务共享网络和磁盘
6. 任务排序可选：不排序 / 直播录制优先 / 下载任务优先
7. 任务列表只保存在本次运行中，关闭程序后普通任务不会恢复
8. 蹲开播仍在「等待开播」面板管理；开播后触发的录制会作为任务出现
9. 「任务内直播与下载并行」默认开启；每任务直播默认 2 路（2–5），视频默认 1 路（1–5），两类额度独立；关闭开关后全部链接按输入顺序串行
10. 密码和归档确认在对应任务详情内操作，刷新页面可恢复；任务下载配置在提交时固定
11. Withny HAR 下载和专用直播监控同样进入队列；任务列表最多保留最近 100 个已结束任务，下载历史照常保存
12. 相同活跃链接会拒绝重复提交；运行任务期间不能更新程序/yt-dlp 或清理临时文件，避免破坏下载
13. 「网络与代理 → 快速检测网络」按当前代理测量吞吐、HTTP 延迟、抖动、失败率和负载延迟；约 20 秒，最多 32 MiB 测试数据（不含协议开销）
14. 检测完成后可预览并应用高性能/高可靠配置；高可靠保持每任务视频串行，并只对任务内普通 yt-dlp 视频限速，避免限制直播码率
15. 检测和应用配置前先完成或取消任务；结果 15 分钟内有效，切换网络或代理后需重新检测；短时检测无法保证所有平台带宽或不漏录
16. FANBOX 请独立建任务，不与其他平台的链接混在同一个任务内；不同任务仍可按并发设置并行


TwitCasting 密码记忆（v2.6.0 起）：
  设置 → 平台专项 → TwitCasting，两个选项均默认关闭。
  “记住密码”：本次运行内按链接复用成功使用的密码。
  “保存密码到 XLSX”：仅在记住密码开启时生效，明文保存到根目录 twitcasting_passwords.xlsx。
  关闭时不自动读取或迁移旧密码表，原有任务密码弹窗与批量内复用仍然可用。
  密码表以明文保存密码，除非获得明确授权，请勿发送给其他人。
=====================================
十七、Rplay 点播、直播与 Twitch 转播
=====================================
1. 点播使用单个 https://rplay.live/play/<内容ID> 链接，不支持任意页面批量抓取。
2. 直播使用 https://rplay.live/live/<创作者ID> 或 /creatorhome/<创作者ID>。
3. 如内容需要登录，先在 Firefox 登录 Rplay，再到「设置」选择「Rplay 登录来源 → Firefox」，按需指定 Rplay Firefox 配置。
4. Rplay 授权不以普通 cookies.txt 代替；账号仍须有对应内容的观看或订阅权限。
5. 点播仅处理当前支持的普通 HLS；直播支持当前接入的 HLS 和授权签名 FLV 路径，从当前时刻录制或等待开播。
6. 平台返回 Twitch 转播状态时，程序通过 Twitch 提取器解析源频道；源频道须仍在直播并可访问。
7. DRM、未知加密、未接入授权协议、转码中或已删除内容会报告限制。Rplay HLS 暂不支持分离音画，请选择合并或受支持的音频输出组合。
8. 本说明描述实现范围，不代表所有 Rplay 内容、直播源和账号均已完成真实下载验证。

=====================================
十八、FANBOX 扫描、预览与内容归档
=====================================
1. 在「设置 → 平台专项 → FANBOX」检查「启用 FANBOX」、凭据文件与「匿名访问」。
2. 登录访问使用在 fanbox.cc 已登录浏览器导出的 Netscape 格式 cookies.txt；仅持有 Cookie 不会获得额外赞助权限。
3. 输入创作者主页 https://www.fanbox.cc/@creator 或单帖链接，可先点击「预览」查看帖子，再筛选并下载所选。
4. 本次任务选项可控制正文格式、原始 JSON、封面、图片、附件、外链清单与评论；评论默认关闭。
5. 可按免费/付费、金额、日期、投稿 ID、标题、附件原名和资源类型筛选；命名预览可检查目录与文件模板。
6. 登录账号可按「所有赞助」或「所有关注」范围扫描；扫描范围与可下载资源仍取决于账号实际权限。
7. 「粉丝卡」支持当前作者或所有赞助作者范围，可选择仅下载粉丝卡；是否可取得仍取决于账号与平台返回。
8. 「内容归档」中可查看帖子、打开归档、导出清单、复制外链和校验资源文件；默认目录为 download/Fanbox/。
9. 外链只收集，不自动下载外部平台内容。已验证文件复用不等于所有目标帖子均已完整归档，请核对任务状态、清单与文件。
10. 文件并发、API 间隔、文件启动间隔、代理策略和每日额度在 FANBOX 设置中单独控制。当前源码会在等待期间每 20 秒续租，较长间隔的修复与发布状态见第十九节。
11. 下载流量与下载记录可在 FANBOX 设置中查看。每日额度是本地计量策略，不代替平台限流规则。
12. FANBOX 请独立建任务，不与其他平台混在同一任务；不同任务可并行，分别处理各自的归档确认。

独立扫描（只输出清单，不下载附件）：
  python ".\视频下载工具v2.7.1-GUI.py" --fanbox-scan "https://www.fanbox.cc/@creator" --output ".\fanbox-manifest.json" --anonymous

归档预览：
  python ".\视频下载工具v2.7.1-GUI.py" --fanbox-download "https://www.fanbox.cc/@creator" --preview --anonymous

--anonymous 只允许访问公开内容。当前源码的扫描与归档 CLI 均读取 FANBOX_ANONYMOUS、FANBOX_COOKIE_FILE 和 USE_COOKIES；显式 --anonymous 或 --cookies PATH 优先于保存设置，只影响本次命令，且不能同时指定。凭据相对路径以工具目录为基准；WebUI 原有设置读取行为保持一致。

十九、FANBOX 六项源码修复与发布状态
=====================================
单任务跨平台切换后的停止路由已在 v2.7.0 修复：关闭任务模式后，完成 FANBOX 再成功启动普通视频批量或 Withny 任务，停止和当前命令查询会跟随实际执行器；启动失败、异常或取消选择不会切换路由。

以下六项已在当前源码修复：
1. 排队任务暂停、从任务列表取消或启动失败后，会清理失效活动记录并恢复为可继续状态；修正配置后无需重启程序即可继续。
2. FANBOX 与其他平台混合输入会在入口被拒绝；请分别创建独立任务，不同任务可并行，归档确认只发给所属执行器。
3. 缩略图和封面按实际资源 URL 确定扩展名；旧失败资源续跑时可修复错误扩展名与路径。
4. 预览后可选择受限帖公开封面；正文与附件仍按访问权限处理，显式 accessible_only 筛选继续排除受限帖。
5. 等待期间每 20 秒续 job、file、asset 租约；异常结束原子保存终态，不再因 180 秒等较长间隔本身残留 running。
6. 扫描 CLI 与归档 CLI 均沿用已保存的匿名和 Cookie 设置，显式 --anonymous 或 --cookies PATH 可覆盖本次设置，两者互斥；WebUI 原有行为保持一致。

本轮没有重新构建、上传或替换已发布的 v2.7.0 EXE 与依赖包；旧附件仍包含原问题。原发布说明与附件 SHA-256 见 RELEASE_NOTES.md，复现及验证记录见 docs/fanbox-six-fixes-validation.md。仍应核对任务日志、归档清单和具体资源状态。
