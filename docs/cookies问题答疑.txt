============================================================
         多平台视频下载工具 Cookie 配置指南
         对应版本：v2.7.0 WebUI（Windows EXE／源码运行版）
============================================================

文件存放：cookies.txt 需与主程序放在同一目录
配置方式：程序默认使用 cookies.txt 文件模式，无需额外设置

工具箱的「生成 Cookie 模板」只创建空白 Netscape 格式模板和说明，不含登录凭证。
真实 Cookie 必须从已登录浏览器导出；已有 cookies.txt 不会被覆盖或自动转换格式。

直播录制补充：YouTube、Twitch、Niconico、TwitCasting 和 Twitter/X Spaces 的登录直播通常需要对应平台 Cookie；Bilibili 高画质或登录直播可使用 cookies.txt；NicoChannel 直播还需要在 Firefox 登录以提取 JWT。Cookie 只提供账号登录态，不能绕过会员、付费、地区或 DRM 限制。v2.6.0 原有各平台直播录制由猫猫葉汐A_spy（GitHub：@maomaoyexi）实现与维护。v2.7.0 PR #18 的全部新增功能由 ErgouTree（GitHub：@ergou10086）贡献，其中 Rplay 登录使用独立 Firefox 授权设置。

------------------------------------------------------------
一、为什么需要 Cookie？
------------------------------------------------------------
- YouTube：会员专属视频、年龄限制内容、受限内容
- Bilibili：1080P及以上画质（必须配置Cookie，详见专属指南）
- Twitch：订阅专属直播/视频、会员内容
- Niconico：720P及以上画质、会员限定内容
- Fantia：登录可见内容、付费会员帖子（必须配置Cookie）
- NicoChannel：会员直播需要在 Firefox 登录并提取 JWT
- TwitCasting：密码保护或会员限定直播需要对应权限
- Twitter/X Spaces：登录 Cookie 可能是访问直播或回放的必要条件
- FANBOX：登录可见、已赞助内容使用对应账号 Cookie；匿名仅限公开可访问内容
- Rplay：登录来源为独立 Firefox 授权设置，普通 cookies.txt 不能替代

不配置Cookie只能下载完全公开的内容，且画质可能受限。

------------------------------------------------------------
二、推荐配置方法（适用于 Cookie 文件模式的平台）
------------------------------------------------------------

使用浏览器扩展导出 cookies.txt 文件（唯一推荐方案）：

1. 安装扩展
   - Chrome/Edge：Chrome应用商店搜索 "Get cookies.txt LOCALLY"
   - Firefox：附加组件商店搜索 "Get cookies.txt LOCALLY"
   - 扩展纯本地运行，不会上传你的Cookie数据

2. 登录账号
   - 打开你需要下载的平台官网（如YouTube/Niconico等）
   - 登录你的账号
   - 多平台使用：依次打开并登录所有需要的平台
   - 单份cookies.txt可包含多个平台导出的 Cookie

3. 导出Cookie
   - 在目标平台的网页上（必须在对应网站页面）
   - 点击浏览器工具栏上的扩展图标
   - 选择导出格式为「Netscape」格式（这是必须的）
   - 导出文件保存到本地

4. 放置文件
   - 将导出的文件重命名为：cookies.txt
   - 放到与 video-downloader-v2.7.0-GUI.exe 同一目录（源码版与 视频下载工具v2.7.0-GUI.py 同目录）
   - 不要放入子文件夹

5. 完成
   - 无需在程序中额外设置
   - 重启程序或直接开始下载即可生效

------------------------------------------------------------
三、各平台 Cookie 专属说明
------------------------------------------------------------

1. YouTube
   - 公开视频可不用Cookie
   - 会员视频、年龄限制视频、被地区限制的视频需要对应账号Cookie
   - 在 youtube.com 页面导出

2. Bilibili（1080p 必读）
   - 标准1080P高清(80)：需登录，无需大会员
   - 1080P高码率(112)：需大会员
   - 4K超清(120)：需大会员
   - 关键：导出Cookie前必须在浏览器中切换到目标画质
   - 详见：docs/bilibili_cookies_guide.txt
   - 在 bilibili.com 页面导出

3. Twitch
   - 公开直播/回放可不用Cookie
   - 订阅专属内容需要已订阅账号的Cookie
   - 在 twitch.tv 页面导出

4. Niconico
   - 不配置Cookie只能下载低画质
   - 720P及以上画质必须配置登录Cookie
   - 会员内容需要对应会员账号
   - 在 nicovideo.jp 页面导出（不要在子域名导出）

5. Fantia
   - 仅支持cookies.txt文件模式，无其他方式
   - 大部分创作者设置了仅登录可见
   - 付费帖子需要账号已订阅对应创作者
   - 必须在 fantia.jp 页面导出Cookie
   - Cookie仅传递登录态，不能绕过付费墙

------------------------------------------------------------
四、常见问题与排查
------------------------------------------------------------

1. 问题：Niconico只能下载低画质
   原因：未配置Cookie，或Cookie已失效
   解决：登录Niconico账号后重新导出cookies.txt

2. 问题：Fantia下载没反应/提示权限不足
   排查：
   - 确认cookies.txt在程序根目录，文件名正确
   - 确认是在fantia.jp页面导出的Netscape格式Cookie
   - 重新登录Fantia后重新导出Cookie
   - 确认账号已订阅对应创作者，浏览器中可正常浏览目标帖子

3. 问题：Cookie配置了还是提示需要登录
   原因：Cookie过期、导出格式错误、导出时未登录，或只生成了空白模板
   解决：
   - 确认导出格式为Netscape，不是JSON或其他格式
   - 在浏览器中确认账号仍处于登录状态
   - 重新登录后重新导出Cookie
   - 确认cookies.txt文件是纯文本，不是.html或其他格式
   - 空白模板不含登录凭证，需用已登录浏览器导出的真实 Cookie 文件替换
   - 生成模板不会覆盖或修复已有文件；旧文件格式错误时请重新导出

4. 问题：多平台混用，部分平台不生效
   原因：导出Cookie时只在一个平台页面，缺少其他平台的Cookie
   解决：
   - 在浏览器中依次打开 youtube.com、twitch.tv、nicovideo.jp、fantia.jp
   - 确认所有平台都已登录
   - 确认扩展的导出范围包含所有目标站点；可选择导出全部站点（如扩展支持）
   - 选择“当前站点”只会导出该站点，不能认为其中已包含其他平台的 Cookie
   - 分别导出时，需将目标站点的 Cookie 记录合并到同一份 Netscape 文件中

5. 问题：导出的Cookie文件能用多久？
   答：通常Cookie有效期为数天到数周，取决于平台设置。
   如果下载突然提示需要登录，重新导出一次即可。

------------------------------------------------------------
五、安全提示
------------------------------------------------------------
1. cookies.txt包含你的登录凭证，请勿分享给他人
2. 不要上传到公共网络空间
3. Cookie失效后重新导出即可，旧文件可直接删除
4. 使用公共电脑后记得删除cookies.txt文件
5. 建议只下载自己账号有权限观看的内容
6. 不要把cookies.txt提交到Git仓库、网盘共享或问题反馈附件
7. 截图和日志反馈前先检查是否包含Cookie内容或账号隐私

------------------------------------------------------------
六、快速检查清单
------------------------------------------------------------
配置Cookie后无法下载时，按此清单检查：

□ 文件名为 cookies.txt（不是cookies(1).txt、cookies.txt.txt等）
□ Cookie 文件位于配置指定的位置；默认与 EXE 或 视频下载工具v2.7.0-GUI.py 同目录
□ 导出格式为Netscape格式（不是JSON、CRT等）
□ 文件首行为 # Netscape HTTP Cookie File
□ 每条 Cookie 为 7 个字段，以实际 TAB 分隔，不是空格或字面量 \t
□ 文件含已登录浏览器导出的真实 Cookie，不能只使用空白模板
□ 导出时在对应平台的网页上，且账号已登录
□ 账号本身有对应内容的观看/订阅权限
□ 文件编码为UTF-8或ANSI（不要用UTF-8 BOM）
□ 重新导出一次Cookie（可能已过期）
------------------------------------------------------------
七、FANBOX 与 Rplay 补充
------------------------------------------------------------
FANBOX：
- 在已登录的 fanbox.cc 页面导出 Netscape Cookie，默认文件为 cookies.txt；也可在 FANBOX 设置中指定凭据文件。
- 「检查」只用于核验凭据状态，实际帖子、评论、附件和粉丝卡仍受账号权限与平台返回限制。
- 匿名访问不能绕过登录或赞助权限；受限帖公开封面不等于正文可访问。
- 独立 --fanbox-scan 当前忽略 FANBOX_ANONYMOUS，需显式 --anonymous；WebUI 和 --fanbox-download 不受此匿名设置问题影响。

Rplay：
- 先在 Firefox 登录，再在设置中选择「Rplay 登录来源 → Firefox」，按需填写「Rplay Firefox 配置」。
- Rplay 授权不以普通 cookies.txt 代替；Firefox 账号必须已有目标内容观看权限。
- Twitch 转播还需要源 Twitch 频道处于直播且可访问，不会把 Rplay 凭据转交 Twitch。
- 不要公开分享 Firefox 配置、会话目录、Cookie 文件或含令牌的日志。
